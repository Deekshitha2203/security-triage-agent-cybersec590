# Security Triage Agent demonstration walkthrough

Use this script for the in-class demonstration or required video if the group does not present. No video has been generated by this document.

The baseline and positive scenarios have now completed through Duke AI Gateway with live external lookups. See [the verified results and saved run links](DEMO_RESULTS.md). To record fresh executions, the commands below create new timestamped run directories and preserve the verified runs.

1. Introduce the case, group members and risk question. Show the Step 1 diagram and explain model, code, tools and human review.
2. Explain that the original N02 cohort has unknown firmware and SSL-VPN configuration. Show the baseline input and its exact DOCX locators. Explain why the honest result is Insufficient evidence.
3. Before recording, privately configure the Duke token. Close the `.env` file and API-key PDF. Confirm the terminal displays only safe setup status.
4. Run `python3 -m triage run --scenario baseline --provider duke --evidence-mode auto`. Show the correlated model tool request and executed results in `model_messages.json` and `tool_trace.json` in the output directory printed by the command.
5. Show the baseline assessment: R6, null rating, Insufficient evidence priority, decisive gaps, source modes and recommended evidence request. Explain that completion of the workflow does not mean the uncertainty is resolved.
6. Show the positive variant's explicit overrides. It is one simulated gateway instance. Run `python3 -m triage run --scenario positive --provider duke --evidence-mode auto`. Explain the affected version, SSL-VPN component, Internet path and supported major consequences, yielding R1 High / Critical.
7. Inspect a cited external payload and environment passage. Show that severity and KEV do not prove local vulnerability or compromise. Show the current cache/live labels and no secrets in outputs.
8. Run `python3 -m triage evaluate` and show the actual testing report. Explain the applicability-change, impact-change, missing/conflicting-evidence and controlled-failure checks. Show the extra internal-path case changing Critical priority to High while rating remains High.
9. Distinguish the scripted replay tests from the real Duke run. Show the live run's demonstration checklist and the actual group member review/signoff. Discuss missing companion files, simulated inputs, unknown downstream paths and limits of the small test set.
10. Show the baseline manifest and sanitized package command. Confirm actual member contributions and AI assistance disclosure. End with the recommended action and evidence needed to change the decision.

Record the final video with a group member's usual screen-recording tool and submit an instructor-accessible file/link. Keep the token, local `.env`, API-key PDF and dashboard secrets off screen.
